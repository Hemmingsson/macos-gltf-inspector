# Tidy the GLTFInspector host (post renderer-split + chrome merge)

Date: 2026-10-01 · Branch: `next-main` · Scope: `GLTFInspector/` (generic + `Engine/` + adapter
folders) and the root `GLTFInspectorTests/` that cover it. Read-only survey; no code changed.

## Answer

The host is in decent shape, but the two merges left four kinds of residue:

1. **Dead code**, about 350 LOC. The biggest piece is `SelectionDetail.swift` plus its tests:
   nothing in production has used it since `19cd8e4`. There are also test-only mappings, a
   focused value nobody reads, and a drop-handler overload.
2. **Unreachable canvas status UI.** `CanvasRegion` only mounts the canvas when the canvas
   state is `.ready`, yet both renderer roots still draw their own loading and failed views.
   The host even declares a second `CanvasStatusView` that shadows PreviewUI's.
3. **Redundant wiring.** Seeding happens through three paths. `wire()` runs from three
   places. `previewSession` is optional but can never be nil, which creates about 20 `?? default`
   branches. `canHideNodes` and `features` are passed in twice.
4. **Two sources of truth for 5 view keys.** Backdrop, floor, auto-rotate, center and
   projection live both in `EngineSettingsStore`'s overlay and in `PreviewSession`, and are kept
   equal by `syncFromSettings()` plus a `DocumentShell.onChange(revision)`. PreviewUI's
   `SettingsStore` seam is a pass-through: `ShellRootView` only hands it back to `seedSession`.

`AppDefaultsStore`, `EngineAppDefaultsBridge` and `EngineSettingsStore` cannot fully collapse
into one, but they can collapse to **two layers**:
- one app-defaults reader/writer, the bridge, which absorbs `EngineAppLookRouting`;
- one per-window "pinned keys" overlay.

`PreviewSession` should stop holding copies of those values.

Out of scope, but spotted: two behaviour bugs (Reset View resets the environment and tone
mapping to Neutral, and two View-menu toggles do nothing on WebKit) and one duplicate
`CameraPreset` enum in RendererRealityKit.

### F2 Unreachable canvas status UI (both renderer roots)

`PreviewUI/Frame/CanvasRegion.swift:47-55` calls `content()` only in `.ready`, and
`ShellRootView.swift:152` passes `canvasState ?? documentState`. The two roots compute
`canvasState` from the same inputs their canvas branches test:

- **WebKit.** In `WebKit/WebDocumentWindow.swift:61-76` vs `:78-104`, the three
  `CanvasStatusView(...)` branches (`:82-84`, `:97-103`) can only run when `canvasState != .ready`,
  and in that state `content()` is never mounted. So the branches, their `register(nil)` calls
  and `@Environment(\.colorScheme)` (`:13`) are dead.
- **Name clash.** The host `CanvasStatusView` (`DocumentShell.swift:141-175`) is used only by
  those branches. It shadows `PreviewUI/Components/CanvasStatusView.swift:5` (same name,
  different init), so it must be deleted together with the branches.
- **RealityKit.** `RealityKit/RealityDocumentWindow.swift:77-83` maps `convert` straight to
  `canvasState`. `PreviewView`'s `.loading` and `.failed` cases (`RealityKit/PreviewView.swift:46-53,64-66,72-88`)
  are therefore unreachable in the window. `PreviewView.State` is still needed as the convert
  state.
- **Related, small: open-failure logging.** `PreviewView.State.loaded` logs `open failed` (`PreviewView.swift:22`),
  and the window logs it again (`RealityDocumentWindow.swift:179`). AGENTS.md §9 expects one
  "open failed". Keep the host one.
- **Related, SwiftUI pitfall.** `RealityDocumentWindow.swift:37` evaluates
  `playbackController ?? EngineAnimationPlaybackController()` in `body`. That allocates a new
  `@Observable` controller and `RealityClipPlayer` on every render while nothing is loaded.
  Fix: make it `@State private var playbackController = EngineAnimationPlaybackController()` and
  reassign it instead of setting it to nil (`:145,152,178`).

**Change.**
1. Delete the host `CanvasStatusView` and the web status branches. `canvas` becomes
   `WebPreviewCanvas(...).onAppear { register(.web(webCanvas)) }`, guarded by `if let webCanvasURL`.
2. Reduce `PreviewView` to `RealityPreviewCanvas` plus `onAppear { registerCommands(commands) }`,
   taking the model rather than the state.
3. Optional, and makes the existing intent explicit: in `DocumentShell.swift:29`, publish
   `canvasState.isReady ? viewport.commands : nil`. Commands registered by the last ready
   canvas otherwise stay in place while the next document loads, because `register(nil)` never
   runs today.

**Risk:** low. Today's behaviour is unchanged, because those views never render. Point 3 is a
small, intended change: the menus are disabled while loading.

**LOC:** about −75.

### F3 Redundant wiring and optional state that cannot be nil

a. **`previewSession` is optional but never nil.** `EngineViewportController.swift:29` is `var previewSession: PreviewSession?`,
   but `init` always assigns `previewSession ?? PreviewSession()` (`:55`), and no test assigns
   nil (grepped). The comment at `:28` ("Nil only in isolated unit tests") is wrong. About 20
   `previewSession?` / `?? default` sites exist only because of it (`:86-121,135-174,261-279`).
   Change it to `let previewSession: PreviewSession`.

b. **`wire()` runs from three places.** `DocumentWindowModel.wire()` (`DocumentWindowModel.swift:77-83`) is called from
   `DocumentShell.onAppear` (`DocumentShell.swift:38`), `seedSession` (`:88`) and `adopt` (`:145`).
   Everything it sets is fixed for the life of the window:
   - `previewSession` was already passed in at init (`:51`);
   - `settings` is per window;
   - the `saveScreenshot` closure is the same each time.

   Set all three once in `DocumentWindowModel.init`. Pass `settings` into the viewport's init;
   `weak var settings` (`EngineViewportController.swift:25-26`) can become `let`, because there is
   no cycle (the store holds no reference back). Then delete `wire()`.

c. **Seeding runs three ways, and `sidebar` is pushed by hand.** The paths are:
   - `beginOpen` → `applySession` (`DocumentWindowModel.swift:118-119`);
   - `ShellRootView.onAppear` → `seedSession` (`ShellRootView.swift:118,168-172`, via `DocumentShell.swift:74`);
   - `DocumentShell.onChange(phase.isReady)` → `seedSession` (`DocumentShell.swift:46-49`).

   `seedSession` (`DocumentWindowModel.swift:86-90`) only adds `engineViewport.sidebar = activeSidebar`
   and `wire()`. Move that assignment into the existing `sidebar` `didSet` (`:24-26`, which
   already rebuilds `selection`). Then both `seedSession` hooks are redundant, and the shell
   passes `seedSession: nil`.

   Risk: the session is re-read when a document becomes ready. The overrides survive
   (`applySessionRemountDoesNotClobberFileLightDim`). Only the per-window environment and tone
   picks made *during* loading would no longer be reset; they can only be made from the View menu
   while a WebKit page is ahead of its panels.

d. **`canHideNodes` and `features` are passed in twice.** Both roots pass
   `canHideNodes: X.features.contains(.nodeVisibility)` to `DocumentWindowModel`
   (`RealityDocumentWindow.swift:24-29`, `WebDocumentWindow.swift:22-27`), and then pass
   `features:` again to `DocumentShell` (`:36` / `:34`). Change it so that:
   - `DocumentWindowModel(documentURL:features:)` stores the features;
   - `DocumentShell` reads `window.features`;
   - `canHideNodes = features.contains(.nodeVisibility)` is derived once.

   Delete `RendererAvailability.canHideNodes`.

e. **Minor.** `DocumentShell.swift:58,63` calls `window.sceneModel` twice per body. That property
   copies the model and remaps validation (`DocumentWindowModel.swift:58-70`). Bind it once with
   `let model = window.sceneModel`.

**Risk:** medium-low. This is wiring only; no state semantics change.

**Verification:**
- `EngineViewportControllerTests`, `RendererSwitchTests`, `HostSidebarModelOverlayTests`.
- AGENTS.md §9 real-window check on both renderers (`-GLTFRenderer webkit`): one "open start"
  and one "open ready", and "Modifying state" ≈ 0.
- Toggle the pills and the View menu, then reopen another file in the same window.

**LOC:** about −60.

### F4 Two sources of truth for the settings-backed view keys

How the values are held today:
- `EngineViewportController` getters (`EngineViewportController.swift:82-110`) read `settings.sessionValue`
  first and fall back to `previewSession`.
- The setters (`:133-163`) write **both** the overlay and `PreviewSession`.
- `syncFromSettings()` (`:72-80`) copies the overlay into `PreviewSession`, triggered by
  `DocumentShell.onChange(of: window.settings.defaultsStore.revision)` (`DocumentShell.swift:40-43`).
- The canvases read `PreviewSession`; the pills read the viewport.
- The test `settingsOverlayTracksDefaultsInGetters` (`EngineViewportControllerTests.swift:155-186`)
  checks that the getter is live *before* the session is synced. That is the dual source made
  visible.
- `PreviewSession.storedBackdrop` (`PreviewSession.swift:28-31`) is a third read of the same key,
  straight from `AppGroupSettings.defaults`. `beginOpen` overwrites it before any canvas mounts.

The settings layers:
- `EngineSettingsStore` (`Engine/EngineSettingsStore.swift`) keeps four typed override
  dictionaries plus `Value.self ==` ladders (`:17-20,72-105`). Its `default(for:)` (`:30-38`)
  duplicates `EngineAppDefaultsBridge.value(for:)` (`Engine/EngineAppDefaultsBridge.swift:24-29`),
  except for the two session-only keys.
- `EngineAppLookRouting` (`Engine/EngineAppLookRouting.swift`, 53 LOC) exists only so the two
  stores share routing.
- `promoteToDefault` (`EngineSettingsStore.swift:51-61`) has no production caller; only
  `EngineSettingsStoreTests` and `MockSettingsStore` use it.

**Change (smallest that leaves one source):**
1. Store the `EngineSettingsStore` overrides as `private var overrides: [String: any Sendable]`, with
   `readSession = overrides[key.name] as? Value`. That deletes the four dictionaries and both ladders.
2. Have `EngineSettingsStore` hold an `EngineAppDefaultsBridge` (default `.shared`) for
   `default(for:)`. Fold `EngineAppLookRouting` into the bridge, its only remaining user, and
   delete the file.
3. Make `PreviewSession`'s five settings-backed properties computed over the window's
   `EngineSettingsStore`: get `sessionValue`, set `setSession`. Observation flows through
   `@Observable` + `AppDefaultsStore.revision`. This lets you delete:
   - `syncFromSettings()`;
   - the `DocumentShell` `onChange(revision)`;
   - `storedBackdrop`;
   - the double writes in the setters;
   - the `settings ?? previewSession` getters.

   `PreviewSession+RealityKit.bindings` keeps working unchanged; its closures go through the
   computed properties.

**Alternative.** Keep the values on `PreviewSession`, replace `EngineSettingsStore` with a
`Set<String>` of pinned keys on the viewport, and keep `syncFromSettings`. That is about the same
LOC, but leaves the sync hop in place. Not preferred.

**Risk:** medium. The live-tracking ("lazy overlay") semantics must hold.

**Verification:**
- Rewrite `EngineSettingsStoreTests` and `EngineViewportControllerTests.settingsOverlayTracksDefaultsInGetters`
  to assert on `PreviewSession`.
- Real window, both renderers: with a window open, change Settings ▸ Preview ▸ Background and
  Floor. An untouched window follows; a window whose pill was toggled does not. Opening another
  file in the window resets the overrides.

**LOC:** about −90. **Depends on F3**, because it touches the same viewport and shell lines.

### F6 Menu commands

- **Two focused values for one thing.** `\.previewCommands` (`PreviewFocus.swift:20-22`, set at
  `DocumentShell.swift:29`) is always `viewport.commands`, and `\.engineViewport` is published
  alongside it (`:31-34`). Both menus read both (`HostViewMenuCommands.swift:10-11`,
  `HostFileMenuCommands.swift:6-7`). Read `viewport.commands` instead (it is an `@Observable`
  stored property) and delete the `previewCommands` entry.
- **File menu.** `HostFileMenuCommands` is a two-struct wrapper with an unneeded `@Bindable`
  (`:19-21`). Make it one `Button` with `.disabled(viewport?.commands == nil)`. Visible change:
  with no window focused, the menu shows a disabled "Export PNG…" instead of the text "No focused
  window", which is the standard macOS behaviour.
- **View menu bindings.** `HostViewMenuCommands.swift:94-161` hand-writes seven
  `Binding(get:set:)` helpers. One generic helper would do, e.g.
  `func bind<V>(_ get: KeyPath<EngineViewportController, V>, _ set: @escaping (V) -> Void)`.
- **View menu symbols.** `menuSymbol` (`:102-112`) duplicates RK's dead `PreviewCamera.CameraPreset.menuSymbol`.
  Keep the host copy and delete RK's (F8).
- **Inconsistency, not tidy.** "Reset View" (`:75-78`) is not disabled when there are no
  commands, unlike Fit and the presets (`:73,90`). This is probably deliberate, because reset
  also resets session state. Leave it.

**Risk:** low. **Verification:** the menus with a window, without a window, and while loading
(on both renderers); the `DesignShortcutsTests`. **LOC:** about −45.

### F8 Mapping duplication: PreviewUI ↔ GLTFCore (`EngineCoreMapping.swift`)

- **Why the pairs exist.** The enum pairs share raw values: `DebugChannel` ≡ `RenderViewMode.Channel`,
  the two `CameraPreset`s, and `ToneMapping.khronosName` ≡ `RenderLook.ToneMapping.rawValue`.
  The duplication is forced by the layering rule: PreviewUI must not import GLTFCore, and the
  appexes do not link PreviewUI.
- **Recommendation.** Keep the exhaustive switches; they turn a new case into a compile error.
  A `rawValue`-based `init!` would save about 40 LOC but loses that guarantee. Not recommended.
  Only delete the unused reverse `CameraPreset` init (F1).
- **Adjacent (renderer scope).** A **third** preset enum, `PreviewCamera.CameraPreset`
  (`RendererRealityKit/PreviewCamera.swift:31`), is bridged by
  `PreviewCamera.CameraPreset(rawValue: $0.rawValue)` (`RealityKit/RealityDocumentWindow.swift:96`).
  That bridge silently becomes "fit" if the names drift. RendererRealityKit already imports
  GLTFCore, so it could put `yawDegrees` and `pitchDegrees` on a `GLTFCore.CameraPreset`
  extension and delete its own enum (including the dead `title` and `menuSymbol`).
  That would cost about −25 LOC in RK, and `CameraFramingTests` would need updating.
