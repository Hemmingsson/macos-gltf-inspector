# Tidy UI: complexity reduction in PreviewUI / DesignSystem / DesignCatalog

Date: 2026-10-01 · Branch `next-main` (after `dda2a88` chrome merge + `b29ad5b`) · Read-only research.

**Question.** Which behaviour-preserving changes reduce complexity in the rebuilt chrome without touching
the approved layout or visuals?

**Answer.** About 1.1–1.3k LOC can go with no visual change, almost all checked by the compiler:

- dead views and wrappers left over from Phase 2 (`InspectorChip`, `InspectorField`, `StatusWarningCard`,
  `OverlayChrome`, the no-op `Theme/`, `OutlinerSectionView`, the S1f custom-row path in `NodeRow`);
- seam fields and members that no view reads (4 `Stats` fields, 2–4 `MaterialInfo` fields,
  `SceneInfo.rootNodeIDs`, `GeometryInfo.hasNormals`, 4 `Availability` members, `SceneModel.node(_:)`,
  `RightInspector.model`, the `Settings` generic on `ShellRootView`);
- copy-paste that a small helper replaces (the inspector section header padding ×10, the issue-summary
  string ×2, `PreviewOpenInItems` ×5);
- about 40 PreviewUI types that are `public` but used only inside the module.

`Models.swift` splits cleanly along its existing `MARK`s. Host code has a second leftover from the
renderer split: a host-side `CanvasStatusView` and the `PreviewView` loading/failed branches, which look
unreachable.

Method: read every file in the three folders, plus host call sites. Every "unused" claim was checked
with `grep -rn --include='*.swift'` across `PreviewUI DesignSystem DesignCatalog GLTFInspector
GLTFInspectorTests GLTFCore RendererRealityKit RendererWebKit PreviewExtension ThumbnailExtension`.
Line numbers are at `b29ad5b`.

### C8 · One status view; host status leftovers (−100 LOC PreviewUI; host part needs a reachability check)

- **PreviewUI.** `Components/SidebarStatusView.swift`, `InspectorStatusView.swift` and
  `CanvasStatusView.swift` are three switches over `ShellDocumentState`. They differ only in the empty-state
  copy and icon, and the canvas version adds a background and an a11y label. Merge them into one
  `ShellStatusView(state:, placement: .sidebar/.inspector/.canvas)` with the per-placement copy kept as it
  is. Rename `Frame/ShellStatusViews.swift` (which holds only `ShellStatusCopy`) to `ShellStatusCopy.swift`.
- **Host (renderer-split leftover).** `GLTFInspector/DocumentShell.swift:141-175` declares a host-internal
  `CanvasStatusView` with the same name as `PreviewUI.CanvasStatusView`, so it shadows it in the host. It
  uses raw `.system(size:)`, `Color(red:)` and the copy "Failed to load model", which disagrees with
  `ShellStatusCopy.failedTitle` ("Couldn’t load model"). `RealityKit/PreviewView.swift:46-51, 72-85` has
  the same spinner and failure UI.
- **Why they look unreachable.** `CanvasRegion.swift:49-54` renders `content()` only when the canvas state
  is `.ready`. RealityKit's `canvasState` mirrors `convert` exactly (`RealityDocumentWindow.swift:77-83`).
  WebKit's maps a failed web phase or failed panels to `.failed` (`WebDocumentWindow.swift:61-75`). So the
  canvas content runs only in the ready case, and these branches would draw only in edge cases, such as
  `webCanvasURL == nil` while the panels are ready.
- **Proposed change.** Replace the host loading/failed bodies with `Color.clear` and keep the
  `register(nil)` side effect. Delete the host `CanvasStatusView`.
- **Risk.** Medium. Confirm unreachability first: add a temporary log or assert, then open an invalid file
  and a missing URL on both renderers.

Split into C8a (PreviewUI only) and C8b (host); their files do not overlap.

    `isExpanded` in `onAppear`. An initial value from `init` (`_isExpanded = State(initialValue:)`) is
    allowed by pitfall 1 and avoids a one-frame collapsed state. Both behave the same when the footer's
    `ViewThatFits` swaps variants (each copy has its own state).
  - The outliner expansion seed in `onAppear` (`OutlinerList.swift:89-92`) is fine.
- **Settings preview hosts.** The ~15 `XPreviewHost` structs that wrap an `@Observable` mock in `@State`
  with a hand-written `init` follow a valid pattern, but they make up most of the preview line count.
  A shared generic `PreviewHost<Mock>` could halve them. Optional.

## Open question (not recommended without visual sign-off)
