# Look probes: RealityKit vs the Khronos web renderer (seam 5)

Measured 2026-09-30 on branch `rs/look-probes`, macOS 27 SDK, this machine. These are the numbers
behind the `RenderLook` → renderer mapping tables. They close research gaps G1, G2 and G6 and
answer "Needs measurement" items 1–3 in `2026-09-30-rendering-validity-and-testing.md`.

## How it was measured

- **Fixtures:** `TestModels/Fixture Models/probes/`, generated by
  `python3 scripts/testdata/make_look_probes.py`. They are:
  - `env-wheel.hdr`, an equirect whose colour encodes only the longitude φ = 2πu:
    R = 0.4(1+cos φ), G = 0.4(1+sin φ), B = 0.4.
  - a mirror sphere (metallic 1, roughness 0)
  - a white rough plane (metallic 0, roughness 1) under one 1 lux directional, 1 cd point or 1 cd spot
  - an emissive ramp
- **Test:** `GLTFInspectorTests/LookProbeTests.swift`. It is opt-in behind a sentinel. Run it with
  `./scripts/testdata/run-look-probes.sh`. It prints `lookprobe …` lines and writes PNGs and JSON
  to `/tmp/GLTFInspector-look-probes/`.
- **Web:** the shipping `WebRendererHost` still page. Tone map is set to
  `"None (Linear mapping, clamped at 1.0)"` at exposure 0 EV. IBL is off unless `setEnvironment`
  is sent. The HDR is served as a model sibling.
- **RealityKit:** the shipping `EntityLoader.loadThumbnail` convert, rendered by a test-local
  `RealityRenderer` with `isToneMappingEnabled = false`. It has no studio IBL. The target is
  `rgba16Float`, or `bgra8Unorm(_srgb)` where noted.
- **Camera:** both renderers use the pixel-diff camera convention (`PixelDiffRealityKit.stillPose`).
  The eye sits on `Ry(azimuth)·+Z`.

| **Yaw offset** (RK yaw matching web rot 90 = Khronos default) | yaw = **π** (180°) | rot 90 | RK yaw = π − Y; web rot = 90 + Y | High for π. RK residual −7…+1° per azimuth, mean −3°. This comes from RK's own IBL filtering, not from any constant yaw |
| IBL radiance gain (mirror, exponent 0 / `iblIntensity` 1) | 0.37–0.43 of 0.40 source (≈1.00 ± 7 %) | 0.3993 of 0.40 (1.00) | env intensity 1:1 → `intensityExponent = log2(envIntensity)` | Medium: RK varies with direction |

## Recommended mapping constants

`RenderLook` yaw is `Y` degrees, where 0 is the Khronos default view. Exposure is `EV`. Environment
intensity is `E`.

| `RenderLook` | → RealityKit | → Web page |
|---|---|---|
| yaw `Y` | IBL entity yaw = `π − Y·π/180` (native 0 is 180° off Khronos) | `environmentRotation = 90 + Y` |
| environment intensity `E` | `intensityExponent = log2(E) + EV` | `iblIntensity = E` (not wired today) |
| exposure `EV` | Stills: render `rgba16Float` with tone map off and multiply by 2^EV before our tone map. Live, or with the system tone map: IBL exponent + EV, punctual × 2^EV, `emissiveIntensity` × 2^EV | `setExposure(stops: EV)` |
| punctual light scale | directional lux × **591**; point lm = cd · 4π · **591**; spot lm = cd · **π** · **591** | as authored (lux, cd) |
| spot cone | inner/outer degrees = **2 ×** glTF half-angle | as authored |
| tone map none | `isToneMappingEnabled = false` + `rgba16Float` (or `bgra8Unorm_srgb`) | `"None (Linear mapping, clamped at 1.0)"`. The page encodes gamma 2.2 |

k = 591 matches the web pixel on a rough white dielectric. The web BRDF there is 0.97/π against
RealityKit's ≈ 1/π. The physical value is 1.2·2⁹ ≈ 614, which is 4 % brighter than the web on
dielectrics. Prefer 591 so the pixels match.

## Product hooks this implies (not done here, product code untouched)

1. **`StillRenderer` encode.** Render into `.bgra8Unorm_srgb`, or tag the `CGImage` with
   `CGColorSpace.linearSRGB`, instead of `bgra8Unorm` + DeviceRGB. This fixes the dark RK
   thumbnails and backdrop. Every RK golden changes once.
2. **Convert light units** (`Shared/Convert/RealityKitConvert.swift` ~218–235):
   - apply ×591 to all three light types
   - use ×π instead of ×4π for spots
   - double the cone angles
   - revisit the −2 EV file-light IBL dim (G4); today it only partly hides that file lights are ~9 EV too dark relative to the IBL
3. **Tone-map-off stills (decision 2, option A)** are feasible without a custom renderer. The float
   target is scene-linear with unit gain. A small Metal/CPU pass can do `2^EV` → PBR Neutral →
   encode.
